# Help Desk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A role-filtered, multilingual, voice-enabled Help Desk: `/Help`, a "?" button on every page, guides as Markdown files in the app, machine translation with in-app native review, and cached Azure voices.

**Architecture:** Guide Markdown lives as embedded resources in `SPIC.Core` so the UI (Web + MAUI, offline) and the API (voice) read the same text. A pure parser/visibility layer in `SPIC.Core/Help` and `Shared/Services` decides what each user sees, reusing a route-access decision extracted from `PageGuard`. A `tools/help-tools` console app checks coverage, translates with Claude, and applies reviewer corrections. The API generates each voice clip once per (text, language) and serves the saved MP3 forever after.

**Tech Stack:** .NET 10, Blazor (Shared Razor library, Web host, MAUI host), ASP.NET Core API, EF Core + PostgreSQL, Anthropic C# SDK 12.36.0 (already in the local NuGet cache), Azure AI Speech REST (no SDK), Bicep.

**Spec:** `docs/superpowers/specs/2026-11-16-help-desk-design.md`

## Delivery parts

Each part ends in working, shippable software:

| Part | Tasks | Ships |
|---|---|---|
| 1. Framework + English pilot | 1–7 | `/Help`, "?" button, role filtering, coverage check, English guides for Publicity, SAS Sample Collection, SAS Lab |
| 2. Languages | 8 | Tamil / Telugu / Marathi for the pilot, labelled "Machine translated" |
| 3. Voice | 9–11 | Listen button, saved voice files, pre-generation after deploy |
| 4. Verification | 12–15 | `/Help/Review` for native speakers, approvals, corrections pulled into files |

Remaining modules (spec §7 step 5) are content-only follow-ups once Part 1 lands; their order is agreed with the user separately.

## Global Constraints

- Shared Razor library only for UI; must work on Web, Android, iOS and Windows.
- No new permission model. Reuse `PagePermission`, `LoginState`, `PageAuthorization`. The only new enum member is `HelpTranslationReview`, appended at the END of `PagePermission`.
- Languages at launch: `en`, `ta`, `te`, `mr`, `hi` (Hindi added by the user on 2026-11-16). Adding a language = a `help.config.json` entry + content files, no code change.
- Screenshots and every test use demo / local data only. Never the live API or live DB. Local DB: PostgreSQL `spicone_dev` on 5432. The Web project's `launch.json` entry points at the LIVE API — point it at the local `SpicAPI` before any preview.
- Migrations are dry-run against the local DB before prod. Prod and infra deploys are run by the user; infra goes `what-if` first.
- Secrets (Anthropic key, Speech key) never committed; Speech key lives in Key Vault.
- Tests go in `SPIC.RegressionHarness` (dependency-free `Check.That` / `Check.Equal` runner; no xUnit). Run: `dotnet run --project SPIC.RegressionHarness` → expected last line `Total: N passed, 0 failed.`
- Coverage check runs by hand only (no CI, no deploy gate).
- Machine translations show a "Machine translated" note until a reviewer approves that section.

## Review Focus

1. **Odd URLs on the "?" button** — query strings, `#fragments`, trailing slashes, different case (`/publicityrequest/EDIT/12?x=1`) must still find the right section. Test: Task 2 `RouteMatchingIgnoresCaseQueryAndTrailingSlash`.
2. **User with no designation opens `/Help`** — must still be sent to `/Welcome`, as today. Test: Task 5 `NoDesignationUserIsSentToWelcomeFromHelp`.
3. **Broken or partial translation file** — a missing section, a stale section or malformed markers must fall back to English for that section and never crash the page. Test: Task 3 `MissingOrMalformedTranslatedSectionFallsBackToEnglish`.
4. **Indian-language text with `&`, `<` or English terms** must produce valid speech requests. Test: Task 10 `SsmlEscapesAndAppliesSayAs`.
5. **Many users tap Listen on a new section at once** — the voice is generated once, and nobody gets a half-written file. Test: Task 10 `ConcurrentRequestsGenerateOnce`.

### Task 2: Guide format, parser, hashing and route matching (`SPIC.Core/Help`)

**Files:**
- Create: `SPIC.Core/Help/HelpModels.cs`, `SPIC.Core/Help/HelpGuideParser.cs`, `SPIC.Core/Help/HelpHash.cs`, `SPIC.Core/Help/HelpRoutes.cs`, `SPIC.Core/Help/HelpMarkdown.cs`
- Create: `SPIC.RegressionHarness/HelpParserTests.cs`; Modify `Program.cs`

**Interfaces:**
- Produces:
  - `public enum HelpConfidence { Source, Ok, Low }`
  - `public sealed record HelpSection(string Id, string Title, IReadOnlyList<string> Routes, IReadOnlyList<string> For, IReadOnlyList<string> Roles, IReadOnlyList<string> Designations, string Body, string? SourceHash, HelpConfidence Confidence)`
  - `public sealed record HelpGuide(string Module, string Language, string Title, string Icon, int Order, IReadOnlyList<HelpSection> Sections, IReadOnlyList<string> Problems)` — `Problems` holds parse warnings (malformed block, duplicate id); parsing never throws on content.
  - `public static class HelpGuideParser { public static HelpGuide Parse(string module, string language, string text); }`
  - `public static class HelpHash { public static string Of(string title, string body); }` — SHA-256 over `title + "\n" + body` with `\r\n`→`\n` and trimmed trailing whitespace per line; lowercase hex, first 16 chars.
  - `public static class HelpRoutes { public static bool Matches(string pattern, string path); public static string Normalize(string path); public static string Sample(string pattern); }` — `Normalize` strips scheme/host, `?` and `#` parts, trailing `/`, lowercases. `{x}` matches exactly one segment. `Sample` replaces each `{x}` with `0` (used for access checks).
  - `public static class HelpMarkdown { public static string ToHtml(string body, string imageBase); public static string ToSpeech(string title, string body); }`

**File format (exact):**

```markdown
---
module: publicity
title: Publicity Material Tracking
icon: bi-megaphone
order: 40
---

::: section raise-request
title: Raise a publicity request
routes: /PublicityRequest, /PublicityRequest/new, /PublicityRequest/edit/{id}
for: PublicityRequest.Entry
roles:
designations:
source-hash:
confidence:

Body markdown...
:::
```

Header lines run until the first blank line; empty values are allowed; list values are comma-separated. Translated files repeat the same ids and fill `source-hash` (the English hash they were made from) and `confidence` (`ok`/`low`). Supported body Markdown: `##`/`###` headings, paragraphs, `**bold**`, `1.` lists, `- ` lists, `> ` note, `![alt](images/file.png)`. Everything else renders as escaped text. `ToHtml` HTML-encodes all text and rewrites image paths to `imageBase + "/" + file`. `ToSpeech` returns the title, then the body with Markdown marks and images removed, list numbers spoken as "Step 1." etc.

  - `MalformedSectionIsReportedNotThrown` — a `::: section` with no closing `:::` → no exception, `Problems.Count==1`, sections parsed before it are kept.
  - `DuplicateSectionIdReported` → `Problems` has one entry naming the id.
  - `HashIgnoresLineEndingsAndTrailingSpaces` — `HelpHash.Of("T","a\r\nb  ")==HelpHash.Of("T","a\nb")`, and a changed word changes the hash.
  - `RouteMatchingIgnoresCaseQueryAndTrailingSlash` — `Matches("/PublicityRequest/edit/{id}", "https://x/publicityrequest/EDIT/12/?a=1#t")==true`; `Matches("/PublicityRequest/edit/{id}", "/PublicityRequest/edit")==false`; `Matches("/PublicityRequest", "/PublicityRequest/new")==false`.

### Task 10: Voice endpoint with saved files and pre-generation

**Files:**
- Create: `SPIC.Core/Help/HelpSpeech.cs` (SSML building, pure)
- Create: `Spic.Infrastructure/Services/Help/HelpSpeechOptions.cs`, `Spic.Infrastructure/Services/Help/HelpAudioCache.cs`, `Spic.Infrastructure/Services/Help/AzureSpeechSynthesizer.cs`
- Create: `SpicAPI/Controllers/HelpController.cs`
- Modify: `SpicAPI/Program.cs` — configure `HelpSpeechOptions` from section `Help`; register `HelpLibrary.FromEmbedded()` as a singleton, `HelpAudioCache` as a singleton and the synthesizer through `IHttpClientFactory`; add `/api/Help/audio` to the `access_token` allowlist next to line 226
- Create: `SPIC.RegressionHarness/HelpSpeechTests.cs`

**Interfaces:**
- Produces:
  - `public static class HelpSpeech { public static string BuildSsml(string text, HelpLanguage lang, IReadOnlyDictionary<string, string> sayAs); }` — the text is XML-escaped. Each glossary term with a `say` value is wrapped in `<sub alias="say">term</sub>` (whole-word, longest first). The output is wrapped in `<speak version="1.0" xml:lang="{locale}"><voice name="{voice}">…</voice></speak>`, where the locale comes from the voice name (e.g. `ta-IN`).
  - `public interface ISpeechSynthesizer { Task<byte[]> SynthesizeAsync(string ssml, CancellationToken ct); }`. `AzureSpeechSynthesizer` POSTs to `https://{region}.tts.speech.microsoft.com/cognitiveservices/v1` with headers `Ocp-Apim-Subscription-Key`, `Content-Type: application/ssml+xml`, `X-Microsoft-OutputFormat: audio-24khz-48kbitrate-mono-mp3` and `User-Agent: spic-help`.
  - `public sealed class HelpAudioCache { public HelpAudioCache(string root, ISpeechSynthesizer synth); public static string KeyFor(string ssml); public Task<string> GetOrCreateAsync(string lang, string ssml, CancellationToken ct); }`
    - Each voice clip is saved once at `{root}/{lang}/{KeyFor(ssml)}.mp3` and reused for every user afterwards.
    - `KeyFor` uses the same normalization as `HelpHash`, applied to the SSML.
    - Generation is guarded by one `SemaphoreSlim` per key, so concurrent requests produce the file once.
    - It writes to `*.tmp`, then `File.Move` to the final name, so no reader ever sees a half-written file.
    - `root` = `{ContentRoot}/Uploads/Help/audio`, which is on Azure Files and survives redeploys.
  - `HelpController` (`[Authorize]`, `api/Help`):
    - `GET audio/status` → `{ enabled: bool }` (whether a Speech key is configured).
    - `GET audio/{module}/{sectionId}/{lang}` → 404 if voice is disabled or the section is unknown. Otherwise it builds the speech text from `HelpLibrary.Localized(...)` (never from client text), builds the SSML with that language's glossary `say` entries, then calls `GetOrCreateAsync`. It returns `PhysicalFile(path, "audio/mpeg")` with `Cache-Control: public, max-age=31536000, immutable` and an `ETag` set to the key.
    - `GET audio/key/{module}/{sectionId}/{lang}` → `{ key }`. The client puts the key in the audio URL (`…?v={key}`), so phones and browsers keep their own copy and re-download only when the text changes.
    - `POST audio/warm` (Admin/SuperAdmin role only) → generates every missing clip for every module, section and language in the background and returns `{ queued: n }`. Run it once after each deploy that changes guide text, so no user waits for first-time generation.
